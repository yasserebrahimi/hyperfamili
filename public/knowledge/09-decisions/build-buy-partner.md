# ساخت، خرید یا مشارکت؛ مرز پیشنهادی

| لایه | پیشنهاد اولیه پژوهشگر | دلیل/شرط |
|---|---|---|
| تجربه فارسی و کارتابل تصمیم |ساخت یا ارتقای موجود |فرایند و داده محلی؛ ازساخت سامانه موازی پرهیز شود |
| POS/ERP موجود |اتصال کنترل‌شده |جایگزینی بدون شناخت، ریسک غیرضروری دارد |
| ESL،ترازو،RVM،کنتور |خرید/اجاره با آزمون پذیرش |مدل دقیق،پروتکل،قطعه و نگهداشت تعیین‌کننده‌اند |
| رسانه/محتوا/چاپ |مشارکت خدمت و قرارداد نتیجه |صرف ابزار،اجرای کمپین را انجام نمی‌دهد |
| سلامت،انرژی،پرواز و شارژEV |شریک متخصص و بررسی مجوز |مسئولیت و ایمنی مستقل از نرم‌افزار است |
| پژوهش/مدل شبیه‌سازی |پروتوتایپ محدود |پیش ازتعهد تجاری،فاصله واقعیت سنجیده شود |

## استعلام فروشنده
محصول و نسخه دقیق،مشتری مرجع هم‌فرمت،دمو باکالای واقعی،قیمت تفکیکی،رابط ومالکیت داده،کار درقطع ارتباط،پشتیبانی وقطعه،معیارپذیرش وطرح خروج. یک معرفی وب،حق فروش/لایسنس/صادرات/خدمات درایران را تضمین نمی‌کند؛ مسیرمجاز با فروشنده و متخصص بررسی شود.

ادعای «بدون خطا»،«موجودی۱۰۰٪»،«سازگاری کامل»،«بازگشت تضمینی» و«بدون نیروی انسانی» باید به دامنه آزمون و تعهد محدود تبدیل شود. خودسامانه نیز نیروی نگهداشت وکار جدید دارد.
