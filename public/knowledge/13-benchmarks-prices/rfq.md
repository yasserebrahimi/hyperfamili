# درخواست استعلام؛ از قیمت صفحه تا پیشنهاد اجرایی

## قالب استعلام قابل‌مقایسه
برای هر طرح یک شناسهBP، دامنه همان کارت و یکی از روش‌های خرید/اجاره/خدمت ارسال شود. درخواست باید پاسخ در جدول تفکیکی بدهد؛ هیچ فرم یا ایمیل در این پژوهش ارسال نشده است.

| فیلد | پاسخ موردنیاز |
| --- | --- |
| هویت عرضه‌کننده | نام حقوقی، رابطه با سازنده و مسئول گارانتی |
| مدل و نسخه | کد دقیق، سال/وضعیت نو یا بازسازی، نسخه firmware/software |
| تعداد و ظرفیت | تعداد مدل، کاربر، کانال، متراژ، throughput و شرایط آزمون |
| قیمت | مبلغ، ارز، واحد، مدت اعتبار و تخفیف مقدار |
| شاملات | سخت‌افزار، ماژول‌ها، کارتخوان، کابل، سازه، licence و API |
| نصب و سایت | برق، شبکه، آب، تهویه، ایمنی، کالیبراسیون و مجوزهای لازم |
| بهره‌برداری | مواد، باتری، روغن/قهوه/ظروف، شارژ، نظافت، قطعات و مسئول خدمت |
| اتصال | نمونه API، Sandbox، شناسه سفارش، Offline و تطبیق پول/کالا |
| کیفیت و پذیرش | دموی مجاز با داده/کالا/نور/صف واقعی، خطاها و توقف امن |
| خروج | مالکیت/دریافت داده، نسخه پشتیبان، انتقال و خاتمه قرارداد |
| مشتری مرجع | نام مشتری و دامنه واقعی قابل تأیید؛ لوگو به‌تنهایی کافی نیست |
| صورتحساب | مالیات، پیش‌پرداخت، اقساط و نسبت پرداخت به پذیرش |

## دو قیمت لازم
قیمت دستگاه/مجوز را جدا از قیمت «عملکرد قابل‌قبول در محل منتخب» بخواهید. برای دو فروشنده، اول مشخصات و شاملات را برابر کنید و سپس قیمت مقایسه شود. نبود قیمت عمومی به معنی گران‌بودن یا نبود محصول نیست.

## نمونه درخواست کوتاه
«برای طرح [BP…] در یک شعبه آزمایشی، پیشنهاد خود را با کد مدل، ظرفیت قابل آزمون، قیمت تفکیکی تجهیز/مجوز/نصب/اتصال/خدمت، مدت اعتبار، اقلام خارج از قیمت و نمونه مشتری مرجع ارائه کنید. وضعیت قطع برق/شبکه و خطای پرداخت نیز در دموی پذیرش نشان داده شود. پیش‌فاکتور نباید به تعهد خرید تعبیر شود.»
